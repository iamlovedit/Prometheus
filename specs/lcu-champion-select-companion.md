# LCU 英雄选择伴随窗口

## 目标

当英雄联盟客户端进入英雄选择阶段时，Prometheus 隐藏完整主窗口，并在
`LeagueClientUx` 主窗口边缘显示一个紧凑的伴随窗口。伴随窗口必须展示当前可获取的
队友战绩，并根据队列类型展示相应的英雄自动化信息。

该功能是独立 WPF 窗口与公开 LCU API 的组合，不向英雄联盟客户端或游戏进程注入代码，
不读取屏幕图像，也不修改 LCU 窗口内容。

## 生命周期

0. “实用工具”与托盘“游戏辅助”菜单中的“选人阶段吸附窗”开关共享状态，默认开启并
   持久化。关闭时立即隐藏伴随窗口，后续英雄选择阶段不再自动显示，也不得隐藏
   Prometheus 主窗口；重新开启后，若当前仍在 `ChampSelect` 且 LCU 窗口可用，则立即
   恢复伴随窗口。
1. `GameflowPhase` 首次进入 `ChampSelect`，且可定位到可见的 LCU 主窗口时：
   - 创建或复用伴随窗口；
   - 将伴随窗口定位到 LCU 边缘；
   - 成功显示伴随窗口后隐藏 Prometheus 主窗口。
   无论伴随窗口是否启用，Prometheus 主窗口的内容区都应在首次进入 `ChampSelect` 时导航到
   比赛信息页；同一英雄选择阶段内的后续快照不得重复强制导航。
2. 同一英雄选择阶段内，用户从托盘手动重新打开 Prometheus 后，不重复强制隐藏主窗口。
3. 离开 `ChampSelect`、LCU 断开、LCU 关闭或 LCU 最小化时，隐藏伴随窗口。
4. LCU 从最小化恢复且仍处于 `ChampSelect` 时，重新显示伴随窗口。
5. “实用工具”中的“开局自动显示双方战绩”开关默认开启并持久化。开启时，游戏阶段首次
   进入 `InProgress` 且双方阵容均已可用后，恢复 Prometheus 主窗口并导航到比赛信息页；
   同一 `GameId` 只触发一次，断线重连和后续阵容/战绩快照不得重复弹出。若应用在游戏进行
   中启动，满足上述条件后同样触发。用户在游戏进行中开启该开关时，若双方阵容已经可用，
   则立即执行一次。
6. 关闭“开局自动显示双方战绩”时，离开英雄选择阶段后不强制弹出 Prometheus 主窗口，
   应用继续驻留托盘。进入 `GameStart`、双方阵容尚未可用或无法取得 `InProgress` 快照时也
   不得提前弹出。
7. 自动恢复主窗口时不得设置全局置顶，也不得使用 `AttachThreadInput` 强抢焦点。窗口应先
   执行普通显示与还原，再尝试 WPF `Activate`；若 Windows 拒绝激活，则使用
   `ShowWindowAsync` 和 `SetForegroundWindow` 尝试前置。原生前置仍失败时使用
   `FlashWindowEx` 闪烁任务栏作为降级提示。所有原生调用失败均不得中断应用，用户仍可
   自行最小化或关闭到托盘。
8. 应用退出时停止窗口跟踪、解除事件订阅并关闭伴随窗口。

## 窗口吸附

- 伴随窗口默认贴在 LCU 右侧外缘；右侧工作区空间不足时改贴左侧。
- 两侧均不足时，窗口贴在 LCU 内部右缘，并限制在当前显示器工作区内。
- 伴随窗口随 LCU 移动、调整大小、跨显示器和 DPI 变化而重新定位。
- LCU 位置或可见状态变化后，伴随窗口应在 500 毫秒内完成同步。
- 伴随窗口无标题栏、不显示任务栏按钮、不抢占 LCU 的键盘焦点。
- 伴随窗口不得使用全局置顶；LCU 被激活时可以把伴随窗口提升到 LCU 之上。
- 伴随窗口在普通非置顶 Z 层中保持位于 LCU 正上方；即使 LCU 当前不是前台窗口，
  `InsideRight` 覆盖模式也不得被 LCU 自身遮挡。

## 展示内容

### 队友战绩

- 使用 `IMatchService.Current.Roster.MyTeam`，排除本地玩家，最多展示四名队友。
- 每名队友展示当前可用的英雄头像、Riot ID、单排段位、最近 20 场胜负/胜率和平均 KDA。
- 加载过程中展示加载状态；LCU 隐藏玩家身份或接口不返回数据时必须如实展示不可用状态，
  不得伪造战绩。
- 阵容与战绩随 `SnapshotChanged` 实时更新。

### 大乱斗与海克斯大乱斗

- 队列 `450` 显示为极地大乱斗；海克斯大乱斗的公开队列 ID `2400` 及国服 gameflow、lobby、
  matchmaking 快照使用的内部 ID `3270` 均显示为海克斯大乱斗。`3270` 通常同时携带
  `GameMode = KIWI`；即使后续内部队列 ID 再次变化，明确的 `KIWI` 模式也必须判定为
  海克斯大乱斗。
- 队列 ID 可来自 gameflow session、lobby 或 matchmaking；过渡快照中的 `0` 不得阻止读取
  后续来源。任一来源明确返回 `2400` 或 `3270` 时必须优先判定为海克斯大乱斗，不得被其他
  来源的 `450`、地图 `12`、模式 `ARAM` 或 `KIWI` 覆盖为普通极地大乱斗。
- 展示本地玩家当前英雄。
- 自动交换开启时，展示当前优先级列表中可从备战席换取的最高优先级英雄；若当前英雄已经
  位于偏好列表中，则当前英雄即为自动化结果。
- 自动交换关闭、没有候选或备战席不可用时，展示明确状态。

### 排位与匹配

- 队列 `420`、`440` 分别显示单双排和灵活排位；其他非大乱斗英雄选择显示为匹配模式。
- 分别展示自动 Ban 和自动 Pick 的开关状态、目标英雄与当前执行状态。
- 当本地玩家对应操作已带有英雄 ID 时，以实际操作英雄为准；否则展示配置中优先级最高的
  候选英雄。
- 没有配置候选或自动化关闭时展示明确状态。

### 推荐符文

- 除队列 `2400` 海克斯大乱斗外，伴随窗口在本地玩家选择或预选英雄后展示推荐符文卡片；
  尚未选择英雄时展示等待状态。海克斯大乱斗不得请求推荐数据，也不得显示符文卡片或占位。
- 峡谷模式优先使用 QQ 英雄详情数据，并按本地玩家的 `AssignedPosition` 选择
  `top`、`jungle`、`mid`、`bottom` 或 `support`；位置不可用时选择样本数最高的可用分路。
  QQ 数据不可用时允许回退 WeGame。队列 `450` 使用 WeGame 的 `aram` 推荐。
- 卡片提供“登场率最高”和“胜率最高”两个方案。胜率方案必须排除明显的小样本异常；没有满足
  样本要求的候选时回退登场率方案。
- 每套方案展示主系、副系、9 个符文、登场率、胜率、样本数（来源提供时）、数据来源与版本或
  更新时间。符文名称和图标使用当前 LCU 的 `perks.json` 映射；任一符文 ID 在当前客户端中
  不存在时，必须禁用应用并展示数据不可用，不得写入过期符文页。
- 英雄、分路、队列或阶段变化时取消旧请求；旧请求即使稍后返回也不得覆盖当前英雄。加载、
  无推荐、外部数据失败和符文资源失效必须展示可区分状态。
- “一键应用”由玩家手动触发，不得自动覆盖符文页。Prometheus 只创建或更新自己命名的托管
  符文页，名称格式为“`英雄名 - 登场率最高符文 [Prometheus]`”或
  “`英雄名 - 胜率最高符文 [Prometheus]`”；切换英雄或方案后应用时同步重命名。不得删除或
  覆盖玩家的其他符文页；LCU 返回成功后还必须重新读取当前符文页并确认名称、主副系与 9 个
  符文完全一致，才能展示“已应用”。英雄名称资源首次返回空结果时必须允许有限重试，不得永久
  缓存空名称；名称仍未解析成功时可以展示英雄 ID 占位，但必须禁用应用，禁止创建以 `#英雄ID`
  开头的托管符文页。
- 一键应用遵守玩家操作日志规范：新建托管页时记录 `rune.page.create`，确认当前页一致后记录
  `rune.page.apply`；两者共享同一 `OperationId`。未连接、失败或无法确认不得记录为成功。

## 容错

- 找不到 LCU 窗口时保留 Prometheus 主窗口，不显示悬空伴随窗口。
- 原生窗口 API 调用失败不得中断 LCU 数据协调器或导致应用退出。
- 英雄名称或图标加载失败时保留英雄 ID/占位状态，其他队友数据继续显示。

## 验收标准

- 进入和离开 `ChampSelect` 能正确控制两个窗口的可见状态。
- 首次进入 `ChampSelect` 时自动导航到比赛信息页，同阶段后续快照不重复导航。
- 实用工具与托盘开关双向同步；关闭后伴随窗口立即隐藏且不再自动弹出，开关状态可跨
  应用启动保持。
- LCU 移动、最小化、恢复和跨显示器时伴随窗口行为符合“窗口吸附”规则。
- 大乱斗、海克斯大乱斗、单双排、灵活排位和普通匹配的展示分支正确。
- 队友列表不包含本地玩家，且不超过四人。
- 自动交换、自动 Ban、自动 Pick 的关闭、未配置、等待、执行和完成状态可区分。
- 除海克斯大乱斗外，选择或切换英雄会加载正确模式和分路的推荐符文；快速切换不会展示旧英雄
  结果，普通大乱斗使用 `aram` 推荐，海克斯大乱斗不请求也不展示推荐符文。
- 登场率/胜率方案可切换，9 个符文均能由当前 LCU 静态资源解析；过期或缺失 ID 禁止应用。
- 一键应用只写入 Prometheus 托管符文页，并在重新读取当前页确认一致后反馈成功；创建与应用
  的成功、失败和拒绝结果具有符合规范的结构化操作日志。
- “开局自动显示双方战绩”默认开启且可持久化；关闭后游戏开始不自动恢复主窗口。
- 首次取得 `InProgress` 双方阵容时自动恢复主窗口并进入比赛信息页，同一局及断线重连不
  重复弹出，下一局可再次触发。
- 主窗口隐藏到托盘或处于最小化状态时会恢复并尝试前置；Windows 拒绝前置时闪烁任务栏，
  且不得使用全局置顶或 `AttachThreadInput`。
- 窗口定位与模式/目标选择逻辑有自动化测试。
- `en-US.xaml` 与 `zh-CN.xaml` 的新增资源保持一致。
