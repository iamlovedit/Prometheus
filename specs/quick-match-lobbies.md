# 快速匹配房间

> 适用范围：主页与系统托盘快速操作、`IGameService` / `GameService` 的匹配房创建能力，以及相关操作日志与测试。

## 1. 目标

主页标题栏提供高频快速入口，玩家点击后创建对应模式的匹配房并进入大厅：

| 模式 | LCU QueueId |
|------|-------------|
| 单双排 | `420` |
| 灵活排位 | `440` |
| 极地大乱斗 | `450` |
| 海克斯大乱斗 | `2400` |

快速入口只负责创建房间，不自动设置位置、不自动发起匹配搜索。单双排与灵活排位的位置选择继续在英雄联盟客户端房间内完成。

标题栏使用分裂按钮：

1. 主按钮显示“快速开始 · {上次模式}”，点击后直接创建上次选择的模式房间。
2. 下拉区域列出四种模式；选择后在空闲阶段创建房间、在已有房间阶段切换队列，并把它保存为新的上次模式。
3. 首次安装、设置损坏或保存值不受支持时默认使用单双排 `420`。
4. 上次模式必须跨应用重启持久化；保存失败时本次运行仍使用玩家刚选择的模式。
5. 系统托盘提供“快速开始”子菜单，第一项直接应用上次模式，后续四项用于立即选择并创建或切换对应模式房间。
6. 主页和系统托盘共享同一份上次模式状态，任一入口切换模式后另一入口必须在本次运行内立即同步。
7. 已处于匹配房间 `Lobby` 阶段时，快速入口保持可用；选择模式后直接把现有房间切换为目标队列，不要求玩家先退出房间。

## 2. 前置条件

1. `IMatchService.Current.ConnectionState` 必须为 `Connected`。
2. 当前 `GameflowPhase` 必须为 `None` 或 `Lobby`。`None` 创建房间，`Lobby` 切换现有房间队列；匹配、就绪检查、选人和游戏阶段不得覆盖当前状态。
3. 同一时间只允许执行一次快速房间创建操作，执行期间整个分裂按钮禁用。
4. 调用前通过 `lol-game-queues/v1/queues` 确认目标队列存在、已启用且 `queueAvailability=Available`。

## 3. LCU 调用与成功判定

创建房间或切换现有房间队列均使用：

```http
POST lol-lobby/v2/lobby
Content-Type: application/json

{ "queueId": 420 }
```

实际 `queueId` 由玩家选择的模式决定。

成功必须满足以下任一条件：

1. POST 响应中的 `gameConfig.queueId` 等于目标队列；或
2. POST 获得 2xx 后，通过有限次数的 `GET lol-lobby/v2/lobby` 查询确认 `gameConfig.queueId` 等于目标队列。

仅“未抛异常”或仅收到空响应不得判定为成功。确认查询必须支持取消，禁止无限轮询。

## 4. 错误与展示

- LCU 未连接或当前阶段不允许操作：拒绝执行并显示本地化提示。
- 队列不存在、关闭或暂时不可用：不发送创建请求，显示模式暂不可用。
- LCU 拒绝、传输异常或最终无法确认目标大厅：显示通用失败提示，技术异常写入安全日志。
- 中英文资源必须同步。

## 5. 操作日志

快速创建匹配房属于 P0 手动操作：

| 字段 | 值 |
|------|----|
| `EventName` | 空闲阶段创建为 `lobby.matchmade.create`，房间内切换为 `lobby.matchmade.change` |
| `Category` | `Lobby` |
| `Origin` | `Manual` |
| `Module` | 主页入口为 `Home`，系统托盘入口为 `Tray` |
| 安全属性 | `QueueId`、`GameflowPhase`、`ConnectionState`、`DurationMs`，失败时可附加 `ErrorCode` / `ErrorType` |

每次操作必须产生且仅产生一条最终结果，结果按实际情况使用 `Succeeded`、`Rejected`、`Failed` 或 `Cancelled`。

## 6. 验收标准

1. [ ] 四个入口分别映射到 `420`、`440`、`450`、`2400`。
2. [ ] 只有 LCU 已连接且处于空闲或房间阶段时入口可用。
3. [ ] 目标队列不可用时不会发送 POST。
4. [ ] 创建请求体仅包含目标 `queueId`。
5. [ ] 通过响应或后续房间查询确认目标队列后才提示成功。
6. [ ] 操作期间不能并发创建多个房间。
7. [ ] 不会自动开始匹配搜索。
8. [ ] 成功、拒绝、失败和取消日志语义准确，日志不包含玩家身份或 LCU 凭据。
9. [ ] 中英文资源保持一致。
10. [ ] 服务和主页 ViewModel 的关键分支具有单元测试。
11. [ ] 快速入口位于主页标题栏，右下角不重复展示四个模式按钮。
12. [ ] 主按钮使用上次选择的模式，下拉选择会立即执行并持久化新模式。
13. [ ] 无设置、损坏设置和不受支持的 QueueId 均回退到单双排。
14. [ ] 系统托盘提供上次模式快捷项和四种模式选择项。
15. [ ] 托盘入口遵守与主页相同的连接、阶段、队列可用性、并发和成功确认限制。
16. [ ] 主页与托盘的上次模式显示和执行目标在本次运行内保持同步。
17. [ ] 已处于 `Lobby` 阶段时可直接切换到四种目标队列，并通过响应或后续查询确认新队列。
18. [ ] `Matchmaking` 及之后阶段仍禁止创建或切换房间队列。
