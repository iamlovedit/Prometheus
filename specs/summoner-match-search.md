# 召唤师战绩搜索与快速预览

> 适用范围：`Prometheus.Modules.Search`、`Prometheus.Modules.Summoner`、
> `Prometheus.Shared` 中的召唤师资料、历史战绩和玩家跳转交互。

## 1. 页面归属

1. “生涯”页面始终表示当前登录召唤师，不得因查看对局中的其他玩家而把生涯页面替换为他人资料。
2. “战绩查询”页面负责展示其他召唤师的完整资料、段位、最近战绩和单局详情。
3. 在战绩查询页面提交 Riot ID 后，结果必须留在当前页面展示，不得自动跳转到生涯页面。
4. 从其他模块请求查看完整召唤师资料时，Shell 必须导航到战绩查询页面，并把目标召唤师作为导航参数传入。

## 2. 搜索结果区域

1. 战绩查询页面包含固定的搜索区和独立的结果 Region。
2. 搜索成功后，结果 Region 复用共享的 `SummonerDetailView` 和 `MatchHistoryView`，不得复制第二套资料或战绩实现。
3. 共享视图必须接收宿主 Region 参数；从资料进入历史战绩、从历史战绩返回时均在原宿主内完成。
4. 新搜索开始时取消上一搜索；只有最后一次搜索结果可以更新页面。
5. 页面至少区分空闲、搜索中、未找到和已显示结果状态。失败日志不得包含原始 Riot ID、PUUID 或其他完整玩家标识。

## 3. 生涯内快速预览

1. 在生涯历史战绩的双方阵容中点击其他玩家时，保持当前生涯和所选对局不变，在内容区右侧打开快速预览抽屉。
2. 抽屉展示目标召唤师头像、Riot ID、等级、单双排、灵活组排和最近 20 场摘要。
3. 最近 20 场按从较早到最近的顺序展示恰好 20 个胜负气泡；绿色对勾表示胜利，红色叉号表示失败，同时提供非颜色文本或图形标识。
4. 战绩少于 20 场时只展示实际返回场次，并按实际场次计算胜负和胜率。
5. 抽屉提供遮罩点击关闭、关闭按钮和“查看完整战绩”操作。
6. “查看完整战绩”关闭抽屉并导航到战绩查询页面显示同一召唤师。
7. 在战绩查询宿主的历史战绩中点击其他玩家时，不打开生涯抽屉，而是在战绩查询结果区域内切换到该玩家。

## 4. 数据与错误处理

1. 召唤师、段位和战绩仍通过 `ISummonerService` 获取；静态图标通过 `IGameResourceManager` 获取，ViewModel 不得直接访问 HTTP。
2. 战绩窗口固定为最近 20 场，与 [后端约定](./backend-conventions.md) 保持一致，不提供“加载更多”。
3. 抽屉重复选择玩家时取消上一加载；关闭抽屉、离开页面或销毁 ViewModel 时必须取消未完成加载。
4. 抽屉加载失败只展示安全的失败状态并允许关闭，不得清空当前对局详情。
5. 搜索无结果、战绩或详情加载失败可按 P1 记录，但不得记录搜索词、完整 Riot ID、PUUID、SummonerId 或响应体。

## 5. 验收标准

1. [ ] 搜索成功后主菜单仍选中“战绩查询”，结果在搜索页显示。
2. [ ] 从其他模块查看完整资料会进入战绩查询页，而不是生涯页。
3. [ ] 生涯历史战绩点击其他玩家会打开抽屉，当前对局和生涯导航不变。
4. [ ] 抽屉显示实际最近战绩的红绿胜负气泡，最多且固定请求 20 场。
5. [ ] 抽屉“查看完整战绩”进入搜索页并显示相同召唤师。
6. [ ] 搜索页历史战绩点击其他玩家仍留在搜索页。
7. [ ] 快速连续搜索或连续点击玩家时，旧请求结果不会覆盖新目标。
8. [ ] 中英文资源键保持对齐。
9. [ ] 新增 ViewModel 行为具有覆盖导航、气泡统计、失败和取消路径的测试。
